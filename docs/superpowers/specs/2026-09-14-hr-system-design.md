# NEXERP 인사관리 전체 설계안

작성일: 2026-09-14. 상태: 검토용 설계안. 이 문서는 구현 완료를 뜻하지 않는다.

## 1. 목표와 설계 범위

직원의 채용부터 퇴직까지 필요한 기능을 모두 개발 가능한 모듈로 나누고, 회사가 사용하지 않는 모듈은 닫을 수 있게 한다. 기능을 닫아도 기존 업무 이력은 보존한다. 전체 설계는 아래 모듈 모두를 개발 대상으로 포함한다. 단계 구분은 개발 순서이며 기능 제외를 뜻하지 않는다.

이번 문서는 전체 구조·모듈 경계·데이터 소유권·업무 흐름과 첫 개발 단위인 공통 기반 및 인사 원장의 상세 설계를 다룬다. 급여 계산식, 평가 산식, 외부 신고 포맷 등은 해당 모듈 개발 전 별도 상세 설계로 확정한다.

기본 전제는 한국어 업무 화면, 여러 회사·사업장, 회사별 정책, 직원 셀프서비스 제공이다. 실제 근무제·급여주기·휴가정책은 회사 설정으로 입력하며 법정 수치나 신고 규격은 이 문서에서 확정하지 않는다. 해당 기능 구현 시 적용 시점의 공식 자료를 검증한다.

## 2. 현재 프로젝트와 구현 방식

확인한 기준: Git `d2dbd68`, README, HANDOFF, access store, auth guard, 회사·사업장 마이그레이션.

- Vue 3·PrimeVue 화면, Cloudflare Worker, Supabase Auth·Postgres·RLS를 사용한다.
- 회사·사업장·계정·역할별 메뉴 권한은 영속화되어 있다.
- 현재 결재함은 메모리 데모이며 인사 업무 테이블과 인사 메뉴는 없다.
- 기존 `admin / approver / user`와 메뉴 접근 권한만으로 인사 데이터 범위를 통제할 수 없다. 특히 현재 admin 메뉴 우회는 인사 데이터 조회 권한으로 사용하지 않는다.
- 기존 회사·사업장 조회는 활성 사용자에게 넓게 허용된다. 이 정책을 직원·급여 테이블에 복사하지 않는다.

| 구조 대안 | 장점 | 비용·제약 | 선택 |
|---|---|---|---|
| 기존 ERP 안에서 도메인별 모듈 분리 | 현재 인증·UI·배포 재사용, DB 트랜잭션으로 업무 일관성 확보 | 모듈 경계를 코드와 권한으로 유지해야 함 | 채택 |
| 별도 인사 애플리케이션 | 인사 배포·운영 독립 | 계정·조직·결재·회계 동기화 중복 | 미채택 |
| 모듈별 독립 서비스 | 서비스별 확장 가능 | 분산 트랜잭션과 운영 복잡성 증가 | 현재 미채택 |

레이어는 기존 규약대로 순수 도메인 규칙 → 리포지토리 → 스토어 → 화면을 따른다. 조회는 RLS로 보호하며 승인·원장 반영·마감처럼 여러 데이터를 함께 바꾸는 작업은 트랜잭션 RPC로 처리한다. Worker는 외부 연동, 비밀키 작업, 파일 발급 및 백그라운드 실행을 담당한다.

## 4. 모듈 사용 설정

기능별 `enabled → draining → read_only → disabled` 상태를 제공한다.

- `enabled`: 권한 범위 내 조회·신청·처리 가능.
- `draining`: 신규 신청을 막고 기존 신청의 승인·반려·취소 및 마감 정리만 허용.
- `read_only`: 기존 자료 조회·허용된 출력만 가능. 변경 작업과 정기 생성 작업 중단.
- `disabled`: 일반 메뉴·직접 URL·API·파일 발급 접근 차단. 관리자 설정에서 상태와 영향만 확인. 데이터 열람은 read_only로 전환한 뒤 별도 데이터 권한으로 수행.

사용자는 메뉴 표시만 숨길 수도 있다. `menu_visible=false`는 표시 설정이며 기능 중단이나 보안 통제로 간주하지 않는다. '모듈 닫기'는 위 상태 변경이다.

설정은 회사 기본값과 사업장 재정의로 구성한다. 회사 상태보다 사업장이 더 넓게 사용할 수 없고, 데이터의 site_id가 없는 회사 공통 기능에는 회사 설정을 적용한다. core·권한·감사·공통 결재는 활성 종속 모듈이 있는 동안 종료할 수 없다.

닫기 전 서버에서 활성 종속 모듈·결재 대기·미마감 기간·외부 전송 중 작업을 계산한다. 차단 사유가 있으면 즉시 disabled로 전환하지 않는다. 정리 대상·담당자·건수를 화면에 제시하고 draining을 선택하게 한다. 진행 중 변경과 상태 전환은 같은 설정 행 잠금으로 직렬화한다.

근태 없이 급여를 쓰는 경우 급여 입력원을 '수동/검증된 파일'로 명시적으로 설정할 수 있다. 근태 연동이 선택되어 있으면 근태 종료를 차단한다. 화면 숨김만으로 입력원을 바꾸지 않는다.

작업 큐는 실행 시에도 현재 모듈 상태를 확인한다. 중단·실패·재시도 상태를 보존하고 재활성화 시 미실행 발생 작업의 미리보기를 제공한다. 중단 기간 전체를 자동 소급 실행하지 않는다.

## 5. 전사 권한등급과 회사 경계

사원·대리는 레벨 1, 팀장은 레벨 4, 대표는 레벨 5에 기본 매핑한다. 레벨 2·3은 회사가 배정한다. 대표 프리셋은 소속 회사의 모든 활성 업무 메뉴와 전사 조회 권한을 제공한다. 기존 기술 관리자와 대표의 업무 권한을 구별하며 시스템 관리 행동은 명시적으로 부여한다. 등급별 권한·직급/직책 매핑·개별 예외·최종 권한 확인을 ERP 시스템 메뉴에서 통합 관리한다.

허용 조건은 활성 계정·AAL2 인증 ∩ 회사 소속 권한 ∩ 모듈 상태 ∩ 행동 권한 ∩ 데이터 범위이다. 메뉴 권한은 탐색 화면에 추가 적용하며, 서버 검증을 대체하지 않는다.

| 역할 프리셋 | 기본 범위 | 대표 권한 |
|---|---|---|
| 직원 | 본인 | 자기 정보 조회, 허용 필드 변경 요청, 신청, 공개된 명세서 |
| 팀장 | 지정 조직·하위 조직 | 팀 업무용 직원정보, 근태·휴가, 배정된 결재 |
| 인사담당 | 지정 회사·사업장 | 직원·조직·발령·계약 관리 |
| 급여담당 | 지정 회사·사업장 | 급여·계좌·세무·보상 관리 |
| 평가담당 | 지정 평가 주기·대상 | 평가 운영 및 공개 범위 통제 |
| 감사자 | 지정 업무·기간 | 허용된 이력 조회, 변경 불가 |
| 시스템 관리자 | 설정 | 모듈·역할 관리. 직원의 급여·민감정보 자동 열람권 없음 |

전사 공통 권한등급·직급/직책 매핑을 사용하며 상세 규칙은 [전사 권한 설계](2026-09-14-enterprise-access-design.md)를 따른다. 기존 전역 역할은 전환 기간 호환용으로만 유지하고 `access_role_assignments`와 회사별 권한으로 확장한다. `read/create/update/submit/approve/close/reopen/export/manage`를 분리한다. 자기 승인 금지를 기본으로 하며 예외는 회사 정책에 명시·감사한다. approver 전역 역할만으로 모든 인사 문서를 승인할 수 없다.

개인 연락처·주소·계좌·신고 식별정보·평가자료는 일반 직원 디렉터리와 분리된 테이블/응답으로 제공한다. RLS는 행 접근을 통제하며 민감 필드 분리는 테이블·열 grant·허용 필드 RPC로 강제한다. 급여담당 역할 부여/회수는 사유와 감사 기록을 남긴다.

사업장·조직·직원 참조는 `(company_id, id)` 복합 외래키로 회사 일치를 강제한다. 사용자가 보낸 company_id를 신뢰하지 않는다. 회사 전환·로그아웃 시 캐시를 폐기하며 모든 쿼리·파일·내보내기에 동일 범위를 적용한다.

## 6. 데이터 모델

모든 업무 테이블에는 UUID, company_id, 감사 열을 둔다. 사업장 데이터에는 site_id를 추가한다. 아래 필드 표는 공통 열을 생략했다. 공통 모듈 카탈로그 같은 정적 정의는 업무 행과 구별한다.

### 6.1 첫 개발 단위의 상세 테이블

| 테이블 | 핵심 필드·제약 |
|---|---|
| `company_memberships` | profile_id, 상태, 유효기간. 회사 접근 자격이며 직원 등록과 별개 |
| `module_settings` | module_key, scope(site/company), site_id, state, menu_visible, revision. 회사 기본 행과 사업장 행 각각 부분 유일 인덱스 |
| `access_roles`, `access_role_permissions` | 회사별 역할, resource/action, 허용 필드 등급. 알려진 리소스만 허용 |
| `access_role_assignments` | profile_id, role_id, scope_kind, scope_id, valid_from/to. 범위 종류별 참조 검증 |
| `hr_employees` | employee_no, legal_name, display_name, is_active. 회사 안 사번 유일·재사용 금지. 로그인 계정 없이 등록 가능 |
| `hr_employee_accounts` | employee_id, profile_id. 회사 내 계정↔직원 연결 각각 유일. 다른 회사의 고용 관계는 별도 연결 가능 |
| `hr_employee_private` | employee_id, 개인 연락처·주소·생년월일 등 필요한 선택 정보. 직원당 한 행, 분리 권한 |
| `hr_employments` | employee_id, 고용형태, 입사일, 종료일, 상태. 재입사는 새 고용 회차. 동일 직원 고용기간 중복 금지 |
| `hr_departments` | code, is_active. 이름·상위조직·사업장 변경은 버전 테이블에서 관리 |
| `hr_department_versions` | department_id, name, parent_id, site_id, valid_from/to. 기간 중복·기준일 조직 순환 금지 |
| `hr_job_codes` | kind(grade/position/family), code, name, sort_order, is_active. 회사·종류·코드 유일 |
| `hr_assignments` | employment_id, department_id, site_id, grade_id, position_id, manager_employee_id, is_primary, valid_from/to. 기준일 주 소속 하나, 겸직 여러 개 |
| `hr_personnel_actions` | employee_id, employment_id, type, effective_date, status, reason, approval_id, revision. 발령 전후 상세 내역 보관 |
| `hr_employee_histories` | employee_id, category(education/career/qualification), 구조화 상세·기간·증빙. 종류별 스키마 검증 |
| `hr_policy_versions` | policy_key, version, effective_from/to, status, validated_payload. 발행한 버전 수정 금지 |
| `audit_events` | actor, action, resource, resource_id, timestamp, request_id, 사유, 마스킹한 변경 내역. 업무 사용자 수정 금지 |

기간은 `[시작일, 종료일)` 반개구간으로 통일한다. 고용 종료일은 첫 비재직일이며 화면의 '마지막 근무일' 입력은 서버에서 다음 날로 변환한다. 날짜는 회사 업무 달력을 따르고 실제 사건 시각은 timestamptz로 저장한다. company timezone 기본 제안은 Asia/Seoul이다.

현재 소속·재직상태는 기준일의 고용·발령 이력으로 조회한다. 과거와 예약 발령을 직원 행의 현재 값으로 덮어쓰지 않는다. 이미 적용한 발령은 취소 삭제하지 않고 정정 발령으로 보정한다. 소급 변경은 마감 급여·근태 영향 검토를 거친다.

## 7. 대표 업무 흐름과 일관성

### 입사·이동·퇴사

합격/직접 등록 → 직원·고용 회차 생성 → 소속 배정 → 계약·입사 체크리스트 → 계정 연결. 직원 생성만으로 계정을 자동 발급하지 않는다. 예약 발령은 승인 후 지정일 적용 작업이 실행하며 발령 ID로 한 번만 반영한다.

퇴사 승인 → 인수인계·장비 회수·정산 요청 → 해당 회사 직원 접근 종료. 다른 회사의 유효 권한이 있는 계정은 전역 비활성화하지 않는다. 회사별 권한은 퇴사 적용 시각 이후 요청에서 서버가 차단한다. 인사 발령과 Auth/장비 외부 작업은 outbox로 연결하며 외부 실패가 인사 이력을 없애지 않는다.

### 휴가

초안 → 제출(근무표로 사용량 계산·잔액 예약) → 결재 → 승인 시 예약을 사용 원장으로 전환 → 취소 승인 시 역분개. 반려·회수 시 예약 해제. 휴가량은 정수 분 단위로 관리하고 일수 표시는 적용 근무시간으로 환산한다. '1일=8시간'을 고정하지 않는다. 차감·예약은 직원 잔액 행 잠금과 요청별 유일키로 중복 방지한다.

### 결재

draft → submitted → in_review → approved/rejected. 허용 시 withdrawn으로 회수. 승인된 문서의 취소는 별도 취소 신청이다. 제출 시 결재선과 원문 버전을 고정하고, 결재자의 퇴사·대결 변경은 재배정 이력으로 남긴다. 마지막 승인은 원장 반영과 같은 DB 트랜잭션으로 실행한다. 외부 전송은 승인 트랜잭션에서 outbox만 생성한다.

### 급여

대상·입력 수집 → 누락 검증 → 계산 → 담당 검토 → 승인·확정 → 명세서 공개 → 이체 자료 생성 → 지급 결과 대사. 급여 확정·파일 생성·실제 지급 성공은 별도 상태다. 세율·보험료율·산식의 버전, 반올림 단위, 일할 기준을 보존한다. 계산식은 허용 연산자로 구성한 검증된 표현식이며 임의 코드 실행을 허용하지 않는다.

확정 후 원본을 덮어쓰지 않고 정정 회차와 차액을 만든다. 근태·휴가 소급 정정은 영향 대상 급여 회차를 표시하고 재정산 요청으로 연결한다. 외부 신고 전송은 접수·반려·완료를 구별하며 자료 생성만으로 신고 완료라 표시하지 않는다.

## 8. 화면 설계

상위 메뉴는 '인사관리', '내 인사정보', '시스템 > 인사 설정'으로 나눈다. 인사관리는 인사기본/근무·휴가/급여·보상/채용·성장/지원업무/보고서 그룹으로 구성하고 닫힌 하위 메뉴만 있는 그룹은 숨긴다.

첫 개발 화면:

1. **인사 모듈 설정**: 회사·사업장 선택, 모듈명·상태·표시 여부·종속 기능·미처리 건수, 종료 영향 미리보기, 변경 사유.
2. **전사 권한관리**: 등급별 메뉴·행동·범위, 직급·직책 매핑, 업무 역할, 사용자별 추가·제한·유효기간, 최종 권한과 부여 근거. 변경 전후 비교.
3. **직원 목록**: 사번·이름·회사·사업장·부서·직급·직책·고용형태·입사일·재직상태. 회사·기준일·조직·상태 필터, 서버 검색·정렬·페이지네이션.
4. **직원 상세**: 기본/고용·소속/발령이력/경력·학력·자격/계약·문서/근태·휴가/급여·보상/지급품 탭. 권한과 모듈 상태에 따라 탭 노출. 민감 필드는 일반 조회 응답에서 제외.
5. **조직관리**: 기준일 조직 트리와 직원 목록, 조직 변경 예약, 겸직 표시, 미배정 직원 목록.
6. **인사발령**: 발령 유형·대상·적용일·변경 전후 비교·사유·결재·영향 내역. 상태별 허용 동작만 표시.

등록·수정은 오류 필드 이동, 저장 충돌 안내, 입력 유지, 중복 제출 방지를 제공한다. 넓은 표는 가로 스크롤과 고정 작업 열을 사용한다. 불러오기 실패·권한 없음·미사용·데이터 없음 상태를 서로 구별한다. 통계는 접근 가능한 데이터만 집계하고 비활성 모듈을 숫자 0으로 표현하지 않는다.

## 9. API·파일·실행 구조

예정 경로: `src/data/hr/`, `src/repositories/hr/`, `src/stores/hr/`, `src/views/hr/`. 공통 결재·모듈·권한·파일은 별도 공통 디렉터리로 분리한다. 기존 메뉴와 라우터에 menuKey·moduleKey·행동 권한 메타를 연결한다.

첫 리포지토리 계약은 `listEmployees`, `getEmployee`, `createEmployee`, `updateEmployee`, `listDepartments`, `saveDepartmentVersion`, `listPersonnelActions`, `submitPersonnelAction`, `getModuleSettings`, `previewModuleTransition`, `transitionModule`이다. 권한 관리는 별도 access 리포지토리를 확장한다. 목록은 filters/asOf/cursor/limit를 받고 items/nextCursor를 반환한다.

쓰기에는 expectedRevision과 requestId를 받는다. revision 충돌은 새로고침·비교 후 재저장하도록 처리하고, 동일 요청 재전송은 기존 결과를 반환한다. 회사·행동·사용자별 idempotency 키에 고유 제약을 둔다.

에러 코드는 `forbidden`, `module_disabled`, `module_read_only`, `revision_conflict`, `cross_company_reference`, `effective_period_overlap`, `insufficient_leave`, `period_closed`, `dependency_active`, `integration_failed`처럼 안정 코드로 매핑한다. 내부 DB 오류와 민감 값은 응답·일반 로그에 노출하지 않는다.

첨부파일은 비공개 저장소에 두고 메타데이터의 회사·직원·문서 권한을 검증한다. 업로드 용량·유형·검사 상태를 관리하며 검사가 끝나기 전 다운로드를 차단한다. 민감 파일은 인증된 다운로드 경로를 사용한다. 일반 파일에 짧은 서명 URL을 쓰는 경우 발급 이력을 남기고 유효기간 동안 즉시 회수가 어렵다는 제약을 반영한다.

파일 가져오기는 임시 적재 → 행별 검증·중복 비교 → 미리보기 → 확정 → 결과 보고 순서로 처리한다. 오류 행은 조용히 누락시키지 않는다. 큰 내보내기는 작업 큐로 처리하고 생성·다운로드 시 권한을 각각 확인한다.

## 10. 개발 순서와 완료 기준

| 단계 | 독립 설계·개발 단위 | 완료 기준 |
|---|---|---|
| 1 | 전사 권한등급·직급/직책 매핑·회사 범위·모듈 설정, 직원·고용·조직 원장 | 회사 경계와 민감정보 분리, 기준일 조회, 모듈 종료 서버 검증 |
| 2 | 영속 공통 결재·파일·알림, 인사발령·계약·입퇴사 | 최종 승인과 원장 반영 원자성, 예약 발령, 문서 접근 제어 |
| 3 | 근무표·근태·휴가·셀프서비스 | 교대·야간 처리, 동시 휴가 차감, 마감·정정, 직원 신청 흐름 |
| 4 | 보상·급여·보험·세무·퇴직정산 | 정책 버전별 검증 사례, 정정 회차, 명세서·지급·신고 상태 분리 |
| 5 | 채용·평가·교육·복지·출장·지급품 | 모듈별 신청~완료, 한도·예산·공개 범위, 외부 연동 계약 |
| 6 | 전체 보고서·증명서·연동·운영 검증 | 권한별 집계·출력, 실패 복구, 보존·복원, 모든 모듈 종료·재개 검증 |

1단계의 발령 테이블은 구조와 조회를 준비하고, 승인 발령 실행은 2단계 공통 결재 완료 후 제공한다. 급여의 기초 보상 데이터 관리는 4단계에서 함께 구현한다. 공통 서비스의 필수 부분은 종속 모듈보다 먼저 만든다.

각 단계는 자체 상세 설계·마이그레이션·도메인 규칙·화면·실제 DB 권한 테스트·인수 시나리오를 갖춘다. 외부 서명·출퇴근 장비·은행·신고 연동은 공급자별 어댑터로 분리하며 자격증명과 테스트 환경 확보 후 실제 연동 완료 여부를 판정한다.

## 11. 검증 계획

- **권한:** 다른 회사 ID를 직접 전송, 일반 직원의 동료 급여 조회, 팀장의 범위 밖 조회, admin 메뉴 우회, 비활성·AAL1 계정, 권한 회수 후 열린 탭/API/파일 접근을 실제 RLS/RPC로 검증.
- **모듈:** 직접 URL·RPC·예약 작업 차단, 미처리 결재가 있는 종료, 상태 변경과 동시 제출, 재활성화 중복 발생 검증.
- **원장:** 재입사, 겸직, 기간 경계, 조직 순환, 예약·소급 발령, 마감 후 정정, 동일 회사 참조 강제 검증.
- **동시성:** 마지막 잔액에 동시 휴가 신청, 결재 더블클릭, 만료 revision 저장, 외부 성공 후 응답 유실·재시도 검증.
- **계산:** 야간·자정 경계·불규칙 근무표, 분 단위 휴가, 급여 소수·반올림·소급 사례를 회사가 승인한 예상 결과와 비교.
- **UI:** 직원·팀장·인사·급여담당 사용자 흐름, 접근성, 조회 실패 복구, 회사 전환 캐시, 출력 범위 검증.
- **회귀:** 기존 계정·MFA·회사·사업장·메뉴·결재함 동작 유지. SQL 텍스트 검사만으로 RLS 실행 검증을 대체하지 않는다.

## 12. 운영 전 확정할 회사별 설정

설계 구조는 위 전제로 진행한다. 운영 데이터와 정책은 도입 단계에서 관리자 설정으로 입력·검증한다.

- 실제 회사·사업장, 인원 규모, 조직·직급·직책, 기존 직원 데이터 가져오기 기준.
- 근무제·근무일·휴일·휴가 발생·이월 정책과 적용일.
- 급여 지급주기·항목·일할·반올림·정산 기준 및 검증 담당자.
- 역할별 접근 범위, 최초 인사/급여 권한 관리자, 결재선·대결 정책.
- 외부 서명·출퇴근 장비·회계·은행·신고 서비스 및 인증 수단.
- 자료 분류별 보존·삭제 정책, 백업·복원 목표, 예상 데이터량에 따른 성능 목표.

이 항목은 구현 누락 표시가 아니라 회사마다 달라지는 운영 설정이다. 외부 연동과 법정 계산의 공급자·규격 검증은 각 모듈의 상세 설계 및 운영 개시 조건으로 관리한다.
