# 겸직·부서 범위 권한 설계

**기준일:** 2026-09-15
**범위:** 인사 기본 모듈의 겸직 원장과 전사 권한 엔진의 조직 범위 판정

## 목적

한 직원이 하나의 주 소속과 여러 겸직을 동시에 가질 수 있도록 고용 회차별 겸직 이력을 보존한다. 직급은 주 소속의 개인 직급을 공통으로 사용하고, 겸직에는 사업장·부서·직책만 지정한다. 겸직 직책에서 파생된 권한은 직원의 기본 권한등급을 올리지 않고 해당 겸직 부서와 하위 조직에만 추가한다.

## 데이터 모델

`hr_secondary_assignments`를 추가한다.

| 필드 | 의미 |
|---|---|
| `id` | 겸직 식별자 |
| `company_id`, `employee_id`, `employment_id` | 회사·직원·고용 회차 |
| `site_id` | 겸직 사업장, null 불가 |
| `department` | 겸직 부서 코드 |
| `position` | 겸직 직책 코드 |
| `start_date` | 권한과 소속 표시가 시작되는 날, 포함 |
| `end_date` | 겸직이 끝나 효력이 없는 첫날, 미정이면 null |
| `reason` | 등록 사유 |
| `created_by`, `created_at` | 등록 감사 정보 |
| `ended_by`, `ended_at`, `end_reason` | 종료 등록 감사 정보 |
| `cancelled_by`, `cancelled_at`, `cancellation_reason` | 미래 겸직 취소 감사 정보 |
| `revision` | 동시 변경 충돌 방지 |

직급은 겸직 행에 저장하지 않는다. 기준일에 유효한 주 소속의 직급을 권한 설명과 화면에 함께 표시한다. 겸직 행은 물리 삭제하지 않는다. 종료는 `end_date`와 종료 감사 필드를 한 번만 채우고, 미래 예약 취소는 취소 감사 필드를 채워 효력 판정에서 제외한다.

모든 회사 참조는 `company_id`를 포함한 복합 외래키로 제한한다. 테이블 직접 권한은 부여하지 않고 RLS를 활성화하며, 보안 정의자 RPC만 읽고 쓴다.

## 기간과 무결성

기간은 `[start_date, end_date)` 반개구간이다. 서울 날짜를 기준으로 상태를 계산한다.

- `planned`: 취소되지 않았고 시작일이 오늘보다 뒤
- `active`: 취소되지 않았고 시작일이 오늘 또는 이전이며 종료일이 없거나 오늘보다 뒤
- `ended`: 취소되지 않았고 종료일이 오늘 또는 이전
- `cancelled`: 시작 전에 취소

겸직 기간은 연결된 고용 회차 안에 있어야 한다. 시작일은 회차 입사일 이상이고, 회차 퇴사일이 있으면 그보다 앞이어야 한다. 종료일은 시작일보다 뒤이며 회차 퇴사일보다 늦을 수 없다. 회차 퇴사일이 새로 정해질 때 종료일이 없거나 더 늦은 겸직은 퇴사일로 자동 마감하고 시스템 종료 근거를 감사 정보에 남긴다.

동일 고용 회차·동일 부서의 미취소 겸직 기간은 겹칠 수 없다. 서로 다른 부서의 겸직은 같은 기간에 여러 개 허용한다. 겸직 부서는 같은 시점의 주 소속 부서와 같을 수 없다. 주 소속이 이동해 활성 겸직 부서와 같아지는 발령은 차단하고 담당자가 겸직을 먼저 종료하도록 안내한다. 비활성 사업장·부서·직책은 신규 등록과 종료일 변경 대상이 될 수 없지만 기존 이력 조회와 겸직 종료는 허용한다.

미래 겸직은 시작일 전까지만 취소할 수 있다. 시작한 겸직은 취소하지 않고 종료한다. 종료일은 오늘 이후로 예약하거나 오늘 날짜로 즉시 종료할 수 있다. 이미 종료된 행의 기간을 다시 열거나 과거 날짜로 소급 변경하지 않는다. 과거 이관과 소급 정정은 별도 기능으로 남긴다.

## 권한 합성

기본 권한등급은 기존 규칙을 유지한다.

1. 사용자 직접 지정 등급
2. 기준일 주 소속 직책 매핑
3. 기준일 주 소속 직급 매핑

겸직 직책 매핑은 이 기본 등급을 변경하지 않는다. 기준일에 유효한 겸직마다 직책 매핑 레벨의 권한을 읽어 별도 파생 허용으로 합성한다. 매핑이 없거나 연결 계정·회사 멤버십·고용 회차가 유효하지 않으면 파생 권한은 생기지 않는다.

겸직 파생 허용은 항상 해당 겸직 부서로 범위를 제한한다.

- 정책의 `company` 또는 `organization_tree` 권한: 겸직 부서와 현재 하위 조직에서 허용
- 정책의 `organization` 권한: 겸직 부서 자체에서만 허용
- 정책의 `site` 권한: 겸직 사업장이면서 겸직 부서 또는 현재 하위 조직인 대상에서만 허용
- 정책의 `self` 또는 `assigned` 권한: 겸직으로 새로 파생하지 않음
- `menu`: 해당 리소스에 유효한 겸직 파생 허용이 하나라도 있으면 메뉴 표시 가능

하위 조직 판정은 현재 `hr_reference_codes`의 활성 부서 `parent_code` 트리를 사용한다. 조직 개편의 과거 계층을 재현하는 기간별 조직 버전은 이번 범위에 포함하지 않는다. 권한은 요청 시점의 현재 조직 트리로 판정하고, 겸직 행에는 당시 선택한 부서·사업장·직책 코드를 보존한다.

개별 `deny`는 기본 등급·역할·겸직 파생 허용보다 우선한다. 좁은 범위의 거부는 일치하는 대상에만 적용한다. 겸직 종료·취소, 고용 회차 종료, 계정 연결 해제, 회사 멤버십 만료, 정책 변경은 다음 요청부터 판정에 반영한다.

## 범위 판정 인터페이스

기존 회사 단위 `private.enterprise_granted` 계약은 유지한다. 대상 행이 있는 모듈이 사용할 범위 인식 함수를 추가한다.

```text
private.enterprise_granted_for_target(
  company_id, resource, action,
  target_site_id, target_department_code
) -> boolean
```

이 함수는 호출자의 기본 정책 권한과 개별 예외를 먼저 판정하고, 부족하면 유효한 겸직 파생 권한을 검사한다. 대상 회사는 호출 인자와 서버가 조회한 행의 회사가 일치해야 한다. 부서나 사업장을 지원하지 않는 회사 전체 작업은 겸직 권한만으로 허용하지 않는다.

최종 권한 확인을 위해 설명 함수를 추가한다.

```text
enterprise_explain_scoped_access(
  company_id, profile_id, as_of,
  resource, action,
  target_site_id, target_department_code
) -> jsonb
```

응답에는 허용 여부, 기본 레벨과 근거, 일치한 정책 권한, 겸직 ID·직책·부서·범위, 적용된 거부 근거를 포함한다. 다른 사용자의 권한 설명은 권한관리 권한으로 보호하고, 본인 설명도 회사 멤버십과 모듈 상태를 검사한다.

현재 영속 업무 모듈 가운데 부서 대상 행을 처리하는 RPC는 새 함수를 사용하도록 전환한다. 아직 데모 데이터만 있는 영업·구매·재고 모듈은 향후 영속 RPC를 만들 때 이 함수를 사용해야 하며, 클라이언트 필터만으로 범위를 제한한 것으로 간주하지 않는다.

## RPC와 권한

다음 RPC를 추가한다.

- `hr_secondary_assignment_history(company, employee)`: 고용 회차별 겸직과 상태 조회
- `hr_prepare_secondary_assignment(company, employee)`: 유효 고용 회차, 가장 빠른 시작일, 사업장·부서·직책, 예상 파생 권한 조회
- `hr_create_secondary_assignment(company, employee, employee_revision, document, reason)`: 즉시 또는 미래 겸직 등록
- `hr_end_secondary_assignment(company, employee, assignment, employee_revision, assignment_revision, end_date, reason)`: 현재 또는 미래 종료일 등록
- `hr_cancel_secondary_assignment(company, employee, assignment, employee_revision, assignment_revision, reason)`: 미래 겸직 취소

등록 문서는 정확히 `{employmentId, siteId, department, position, startDate, endDate}` 키를 사용한다. `endDate`는 null을 허용한다. 준비 응답은 주 소속 직급, 직책 매핑 레벨, 권한 범위 설명, 기준정보와 쓰기 가능 상태를 반환한다.

조회에는 `hr.core/read/company`, 등록·종료·취소에는 `hr.core/update/company`가 필요하다. 등록과 종료 예약은 인사 기본 모듈이 `enabled`일 때만 허용한다. 기존 미래 겸직의 취소는 `enabled` 또는 `draining`에서 허용한다. `read_only`와 `disabled`에서는 변경을 차단한다.

쓰기는 회사 행, 직원 행, 고용 회차, 겸직 행 순서로 잠근다. 직원 버전과 겸직 버전을 검사하고, 같은 트랜잭션에서 기간 중복·주 소속 충돌·기준정보·모듈 상태를 다시 검증한다. 원문 DB 오류는 클라이언트에 노출하지 않는다.

## 기존 흐름과의 연결

- 주 소속 발령 등록 시 발효일에 같은 부서의 활성·예정 겸직이 있으면 차단한다.
- 퇴사 발령과 고용 회차 종료 시 해당 회차의 겸직 종료일을 퇴사일로 맞춘다.
- 퇴사 발령 취소는 자동 마감된 겸직을 다시 열지 않는다. 담당자가 새 겸직을 등록해야 한다.
- 재입사 회차에는 이전 회차 겸직을 복사하지 않는다.
- 기준정보 비활성화 검사는 현재·미래 미취소 겸직의 사업장·부서·직책 참조를 포함한다.
- `private.hr_module_pending`은 미래 발령·미래 고용 회차·미래 겸직·미래 겸직 종료 예약을 합산한다.

## 화면

직원 상세의 고용 이력 아래에 **겸직** 영역을 추가한다. 고용 회차별로 현재·예정·종료·취소 겸직을 표시하며, 각 카드에는 기간, 사업장, 부서, 직책, 공통 사용 직급, 상태와 권한 범위 설명을 보여준다.

`겸직 등록`은 시작일, 선택적 종료일, 사업장, 부서, 직책, 사유를 받는다. 저장 전 검토 화면에서 주 소속, 겸직 기간, 겸직 직책 매핑 레벨, 추가되는 부서 범위와 충돌 여부를 보여준다. `겸직 종료`는 종료일과 사유를 받고, `예정 취소`는 영향 확인과 사유를 요구한다.

입력마다 연결된 화면 라벨과 필드별 오류를 제공한다. 제출 실패 시 첫 오류로 포커스를 이동하고, 저장 중 버튼을 비활성화하며 성공·실패 상태를 알린다. 복잡한 권한 설명은 입력 뒤 검토 단계에서 점진적으로 노출한다. 375px에서는 한 열, 넓은 화면에서는 두 열로 배치하고 모든 모바일 입력·버튼 높이를 44px 이상으로 유지한다.

## 오류와 복구

- 직원·겸직 버전 충돌: 최신 이력과 준비 데이터를 다시 불러오도록 안내
- 기간 중복 또는 주 소속 충돌: 충돌 부서와 기간을 표시하고 날짜·부서를 수정하도록 안내
- 고용 회차 밖 날짜: 선택 가능한 시작·종료 범위를 표시
- 비활성 기준정보: 활성 사업장·부서·직책을 다시 선택하도록 안내
- 매핑 없는 직책: 등록은 허용하되 추가 권한이 없음을 검토 화면에 명시
- 모듈 상태 변경: 입력을 보존하고 현재 상태에 맞는 가능한 동작을 안내
- 회사·사용자·직원 전환 중 늦게 도착한 응답: 화면에 반영하지 않음

## 검증

실제 001~008 마이그레이션 위에 새 마이그레이션을 적용해 검증한다. 같은 부서 기간 중복, 여러 부서 동시 겸직, 시작·종료 경계, 미래 취소, 주 소속 충돌, 퇴사 자동 마감, 재입사 격리, 기준정보 비활성화, 모듈 진행 건, 회사 경계, RLS와 감사 필드를 포함한다.

권한 검증은 기본 레벨 불변, 직책 매핑 파생, 정확한 부서와 하위 조직, 다른 부서·사업장 거부, 개별 deny 우선, 계정 해제·퇴사·기간 만료 즉시 종료, 메뉴 요약과 직접 RPC 판정 일치를 포함한다.

프런트엔드는 저장소 응답 형식, 오류 정제, 입력별 검증, 검토 단계, 중복 제출 방지, 사용자·회사·직원 전환 시 오래된 응답 폐기를 검증한다. 전체 Vitest, ESLint, 프로덕션/PWA 빌드와 1440px·375px 실제 렌더링을 수행한다. 운영 DB 적용과 배포는 별도 범위다.
