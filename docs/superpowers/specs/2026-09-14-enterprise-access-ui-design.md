# 전사 권한관리 UI 설계

2026-09-14. ui-ux-pro-max를 적용한 화면 설계. [권한 정책](2026-09-14-enterprise-access-design.md)을 기준으로 하며 실제 권한 판정은 서버가 수행한다.

## 디자인 방향

기존 Vue 3·PrimeVue Aura·ERP 사이드바·색상 토큰·한글 글꼴을 유지한다. 검색에서 확인한 Minimalism & Swiss Style의 명확한 계층·그리드·고대비를 적용한다. 함께 반환된 Hero + Features + CTA는 업무 관리 화면에 부적합하므로 적용하지 않는다. 새 폰트·애니메이션 라이브러리·폼 라이브러리는 이 설계에 필요하지 않다.

제목 24px, 본문·입력 16px, 표 14px, 보조 설명 13px를 기준으로 한다. 간격은 8/12/16/24px, 입력·행 작업의 조작 영역은 최소 44px로 한다. 기본 표 행은 48px 이상이며 긴 한글은 잘라 숨기기보다 줄바꿈한다. 색은 기존 semantic primary/surface/text/danger 토큰을 사용한다. 허용·차단·상속·미설정은 텍스트와 아이콘을 함께 표시한다.

## 공통 화면

시스템 > 권한관리에서 회사 선택, 제목·설명, 네 개의 탭을 제공한다. 회사 선택기는 항상 표시하고 회사 미선택 상태에서는 편집을 잠근다. 탭은 권한등급 / 직급·직책 매핑 / 사용자 권한 / 최종 권한 확인이다. 탭과 선택 대상을 URL에 반영하되 민감한 검색어는 URL에 담지 않는다.

변경 작업은 초안 편집 → 영향 확인 → 변경 사유 입력 → 적용 순서다. 권한표 체크 즉시 저장하지 않는다. 하단 작업 영역에 변경 항목 수, 되돌리기, 영향 확인 버튼을 제공한다. 변경되지 않은 경우 적용 버튼은 비활성화한다. 화면·회사·등급 이동 시 미저장 편집을 유지할지 폐기할지 선택하도록 한다.

## 1. 권한등급

1024px 이상에서는 왼쪽 240px 등급 목록과 오른쪽 가변 편집 영역을 둔다. 등급 목록에 레벨·이름·연결 사용자 수를 표시하고 선택은 테두리·배경·텍스트로 구별한다.

오른쪽 상단은 이름, 설명, 다른 등급에서 복사, 연결 사용자 보기다. 그 아래 검색·업무 영역 필터와 권한 표를 배치한다. 표 열은 메뉴명 / 메뉴 접근 / 조회 / 등록 / 수정 / 승인 / 다운로드 / 상세다. 리소스가 지원하지 않는 행동은 체크박스 대신 '해당 없음'을 표시한다. 마감·재개·시스템 관리는 상세 패널에서 조정한다.

행동별 범위는 '조회: 회사 전체 / 수정: 본인'처럼 해당 행동과 붙여 표시한다. 공통 범위 선택 하나가 모든 행동에 암묵적으로 적용되지 않게 한다. 업무 그룹 전체 선택은 현재 필터 범위인지 그룹 전체인지 문구로 명시하고 부분 선택 상태를 제공한다. 대표 레벨 5의 전사 조회·민감정보 권한은 별도 요약에서 보인다.

## 2. 직급·직책 매핑

직급/직책 전환, 연결됨/미연결 필터, 검색을 상단에 둔다. 표는 코드명 / 구분 / 연결 등급 / 적용 시작·종료 / 영향 인원 / 작업 순서다. '직책 연결이 직급보다 우선' 안내를 항상 표시한다.

편집 패널에서 현재 연결과 변경할 등급·적용일을 비교한다. 같은 기간 중복과 종료일 오류를 필드 아래 표시한다. 영향 확인에서는 변경 전→후 레벨, 권한이 늘거나 줄어드는 사용자, 예외가 유지되는 사용자를 구별한다. 예시 데이터라면 명확히 '예시'로 표시한다.

## 3. 사용자 권한

사용자 목록은 이름·사번·직급·직책·기본등급·예외 여부를 보여준다. 선택 시 상세는 기본등급 근거, 업무 역할, 개별 허용·제한, 적용 기간으로 나눈다. 자동 등급은 읽기 전용으로 표시하고 직접 지정은 별도 행동으로 제공한다.

예외 추가 폼은 리소스 → 행동 → 범위 → 허용/차단 → 기간 → 사유 순서다. 같은 대상에 deny가 적용되면 '급여담당 역할의 허용보다 개별 제한이 우선합니다'처럼 결과를 설명한다. 역할 제거와 삭제된 기록 조회를 구별한다. 복수 사용자 일괄 변경은 영향 검토를 거치며 회사가 다른 사용자를 한 번에 적용하지 않는다.

## 4. 최종 권한 확인

사용자·회사·기준일 선택 후 메뉴별 허용/제한 결과를 표시한다. 메뉴를 펼치면 행동별 범위와 근거가 나온다. 특정 문서·조직을 선택하면 그 대상에 대한 판정도 확인할 수 있다.

결과는 '허용 / 제한 / 미설정 / 확인 실패'로 구별한다. 판정 근거는 계정·회사 → 모듈 상태 → 직책/직급 등급 → 추가 역할 → 개별 제한 → 문서 상태 순서로 보여준다. 미래 기준일은 '예정 권한 미리보기'라고 표시하며 현재 접근권한이 바뀌지 않음을 설명한다.

## 상태·접근성·반응형

- 로딩은 표 구조를 유지하는 스켈레톤과 상태 문구로 표시한다. 조회 실패 시 빈 목록 대신 재시도를 제공한다.
- 저장 중 중복 적용을 막고 편집 내용은 유지한다. revision 충돌은 최신 변경과 내 초안을 비교하게 하며 자동 덮어쓰지 않는다.
- 저장 완료는 적용 버전·시각과 짧은 상태 알림을 제공한다. 마지막 관리자 제거 등의 차단은 이유와 수정할 항목을 표시한다.
- 표 체크박스 라벨에는 등급·메뉴·행동을 포함한다. 탭은 키보드 이동을 지원하고 패널 종료 후 트리거로 포커스를 복원한다. 오류 요약에서 첫 오류 입력으로 이동한다.
- 본문 명도 대비 4.5:1, 조작 경계·포커스는 3:1을 검증한다. 색만으로 권한을 표현하지 않는다. reduced-motion에서는 이동 애니메이션을 줄인다.
- 768~1023px는 등급 목록을 상단 선택기로 전환한다. 375~767px는 메뉴별 카드를 펼쳐 행동을 편집한다. 다열 표는 데스크톱에서만 사용하고 페이지 전체 가로 스크롤을 만들지 않는다.
- 고정 저장 영역은 하단 여백과 키보드 포커스 scroll-margin을 확보해 마지막 입력을 가리지 않는다. 확대 200%에서도 주요 동작을 수행할 수 있게 한다.

## 구현 연결 및 인수 시나리오

기존 MenuPermissionManagement.vue의 역할 선택·초안·변경 취소 흐름을 재사용할 수 있지만 기존 role_menu_permissions 저장 함수에 새 등급을 억지로 넣지 않는다. 신규 공통 권한 API·정책 버전을 연결한 뒤 기존 메뉴 경로를 새 화면으로 전환한다.

검증 시나리오는 사원·대리 레벨 1 연결, 대리+팀장 레벨 4 우선, 대표 전사 조회, 레벨 1 급여담당 추가, 개별 deny 우선, 미래 발령, 회사 전환 중 초안, 동시 편집 충돌, 모바일·키보드 조작이다. 화면만 완성된 상태와 서버 권한까지 적용된 상태를 구별해 보고한다.
