# 조직·직급·직책과 직원정보 정정

## 사용 흐름

직원 명부 안에서 회사별 조직·직급·직책 기준정보를 관리한다. 이름과 코드를 등록하면 직원 등록 및 주 소속 발령에서 목록으로 선택할 수 있다. 조직에는 상위 조직을 지정할 수 있으며 자기 자신이나 하위 조직을 상위로 지정하는 순환 관계는 허용하지 않는다.

기준정보 코드는 등록 후 바꿀 수 없다. 코드가 발령 이력과 권한 매핑의 연결값이므로 명칭 정정은 이름을 변경하고 새로운 구분은 새 코드로 등록한다. 직급·직책과 권한등급의 매핑은 기존 전사 권한관리에서 별도로 저장·발행한다. 기준정보를 등록했다고 권한이 자동으로 생기지는 않는다.

현재 소속·입사 예정·미취소 예약 발령에 사용 중이거나 활성 하위 조직이 있는 기준정보는 비활성화할 수 없다. 먼저 소속 변경이나 예약 발령 정리를 진행한다. 과거 이력만 남아 있으면 비활성화할 수 있으며 이전 기록은 보존한다. 비활성 항목은 신규 등록·소속 변경에 선택하지 않는다. 퇴직 처리는 비활성 기준정보 때문에 차단하지 않는다.

## 직원정보 정정

직원 상세에서 이름·입사일을 변경 사유와 함께 정정한다. 저장 전 변경 전후를 확인하고 입사일 변경이 접근 상태에 미치는 영향을 확인한다. 입사일을 미래로 바꾸면 해당 날짜 전까지 연결 계정의 회사 접근이 중단될 수 있다. 이미 기록된 발령보다 늦은 날짜로 입사일을 바꿀 수 없다. 취소된 발령도 이력 일관성 검사에 포함한다.

정정 이력에는 변경 전후 이름·입사일, 사유와 시간이 표시된다. 서버는 작업자도 보존하며 정정마다 직원 버전을 증가시킨다. 같은 직원을 다른 화면에서 수정했으면 최신 정보를 불러온 뒤 다시 검토한다.

사번·계정 연결 및 과거 소속은 이 정정으로 변경하지 않는다. 소속은 발령으로 변경하며 계정 재연결·재입사·발령 소급 정정은 후속 범위다.

## 권한과 적용

현재 인사관리와 같은 회사 전체 `hr.core` 권한을 사용한다. 조회 권한으로 기준정보·정정 이력을 볼 수 있고, 수정 권한이 있어야 기준정보 저장과 직원 정정을 할 수 있다. 기술 관리자 자동 우회는 없다. 회사 또는 계정 전환 시 조회 결과·편집창·정정 이력을 초기화한다.

`20260914000500_hr_reference_catalog.sql`을 001~004 이후 적용한다. 기존 직원·발령에 사용한 조직·직급·직책 코드와 기존 권한 매핑 코드는 기준정보로 이관하며 최초 이름은 코드와 같다. 운영자는 실제 표시 이름을 정리할 수 있다. 기존 발령과 발행 정책은 수정하지 않는다.

조직 계층은 현재 상태를 관리한다. 기준일별 조직 버전, 겸직, 조직도에 따른 직원 조회 범위 확대는 아직 구현하지 않았다. 회사별 인사 기본 사용 상태와 메뉴 표시는 006에서 추가했다. [모듈 설정 안내](hr-modules.md)를 참조한다. 운영 DB 적용과 배포는 이번 작업에서 수행하지 않는다.
