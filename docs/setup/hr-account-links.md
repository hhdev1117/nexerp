# 직원 로그인 계정 연결 운영 안내

## 현재 구현

직원 상세의 **로그인 계정 연결**에서 기존 직원에 로그인 계정을 연결·교체·해제한다. 연결 가능한 대상은 해당 회사의 최신 발행 정책에 등록된 활성 계정이며, 같은 회사의 다른 직원에게 이미 연결된 계정은 제외한다.

연결 전 현재 계정, 변경할 계정, 직원의 현재 직급·직책으로 계산한 권한 레벨과 사유를 검토한다. 계정에 직접 지정한 레벨이 있으면 이를 우선하고, 없으면 직책 매핑 후 직급 매핑 순서로 계산한다. 화면의 값은 발행 정책을 미리 보여주는 것으로 권한을 새로 만들지 않는다.

## 권한과 상태 처리

인사 기본 모듈의 회사 전체 조회 권한이 있어야 연결 정보와 이력을 볼 수 있다. 수정 권한이 있어야 연결을 변경할 수 있다. 읽기 전용·진행 건 정리 상태에서는 변경이 차단되고, 사용 중지 상태에서는 조회도 차단된다.

퇴사한 직원에게 새 계정을 연결할 수 없다. 기존 연결은 퇴사 후에도 감사 이력으로 유지하며 담당자가 연결을 해제할 수 있다. 연결·교체·해제는 직원 버전을 검사하고 같은 회사 안에서 계정 중복을 차단한다.

계정 연결을 해제하면 직원의 재직 정보가 더 이상 그 계정의 직급·직책·소속을 덮어쓰지 않는다. 발행 정책에 직접 레벨·역할·개별 권한이 남아 있다면 그 정책 자체의 접근은 계속될 수 있으므로 필요하면 전사 권한관리에서도 함께 회수해야 한다.

## 데이터와 감사

`hr_employee_account_links`에 변경 전후 계정, 사유, 작업자, 시각을 보존한다. 직원 원장의 `profile_id`와 버전은 한 트랜잭션에서 변경한다. 원장과 감사 테이블은 직접 접근을 허용하지 않으며 RPC가 현재 사용자·회사·모듈 상태·발행 권한을 검사한다.

## 적용과 검증

001~006 이후 `20260914000700_hr_account_links.sql`을 적용하고 앱을 배포한다. 이번 작업에서는 운영 DB 적용과 배포를 수행하지 않았다.

전체 Vitest 67개 파일·783개 테스트, ESLint, 프로덕션/PWA 빌드를 통과했다. 신규 PostgreSQL 실행 검증 38개는 실제 001~006 마이그레이션, 발행 정책, 직급·직책 매핑, 중복·퇴사·모듈 상태·감사 이력을 포함한다. 실제 컴포넌트를 1440px와 375px로 렌더링해 가로 넘침과 브라우저 오류가 없음을 확인했다.
