# 회사별 인사 모듈 사용 설정

## 현재 적용 범위

`시스템 > 인사 모듈 사용 설정`은 활성 기술 관리자와 2단계 인증으로 접근한다. 인사 기능이 중지되어도 이 설정 경로는 유지되며, 관리자라는 이유만으로 직원 데이터를 조회할 수 있는 것은 아니다.

현재 동작하는 모듈은 직원 명부·발령·기준정보·정정 기능을 묶은 **인사 기본**이다. 나머지 인사 모듈은 개발 예정으로 표시하고 활성화할 수 없다. 회사별 설정만 제공하며 사업장별 재정의는 후속 구현이다.

## 상태

| 상태 | 조회 | 신규 등록·발령·정정·기준정보 변경 | 예약 발령 취소 |
|---|---|---|---|
| 사용 | 기존 권한에 따라 허용 | 기존 권한에 따라 허용 | 기존 권한에 따라 허용 |
| 진행 건 정리 | 허용 | 차단 | 기존 수정 권한이 있는 담당자에게 허용 |
| 읽기 전용 | 허용 | 차단 | 차단 |
| 사용 중지 | 차단 | 차단 | 차단 |

각 ‘허용’은 해당 회사의 발행된 인사 권한을 별도로 요구한다. 상태 설정은 사용자 권한을 새로 부여하지 않는다. 기존 설정이 없는 회사는 ‘사용·메뉴 표시’가 기본값이며, 기존 정책 권한 검사는 그대로 적용된다.

## 메뉴 숨김과 기능 중단

‘메뉴 표시’를 끄면 사이드바에서만 사라진다. 권한이 있는 사용자의 직접 주소와 API 접근은 유지된다. 실제 기능을 닫으려면 ‘사용 중지’를 선택한다. 사용 중지는 메뉴·직접 주소·인사 RPC를 차단한다.

인사 모듈을 닫아도 직원·발령·정정·기준정보 이력을 삭제하지 않는다. 다른 ERP 영역에서 사용하는 현재 재직 상태와 직급·직책 권한 판정도 유지한다. 퇴직자의 접근을 다시 열거나 인사 이력을 무시하는 방식으로 중단하지 않는다.

## 예약 발령 정리

아직 발효되지 않은 미취소 발령이 있으면 ‘읽기 전용’ 또는 ‘사용 중지’로 바꿀 수 없다. ‘진행 건 정리’ 상태에서 기존 예약 발령의 적용을 기다리거나 담당자가 취소한 뒤 전환한다. 이 상태에서도 기존 예약 발령은 지정 날짜에 적용되며 새로운 발령은 추가할 수 없다.

설정 화면의 예약 건수는 검토 시점의 안내이며 저장 시 서버가 다시 검사한다. 상태 전환과 인사 쓰기는 회사 잠금으로 순서를 정하므로 동시에 새 발령을 등록하여 종료 검사를 우회할 수 없다.

변경 전 회사·대상 모듈·전후 상태·메뉴 표시를 확인하고 사유를 입력한다. 다른 관리자가 먼저 저장한 경우 버전 충돌을 표시하므로 최신 설정을 다시 불러온다. 변경 전후, 사유, 작업자는 감사 이력으로 보존한다.

## 적용 순서와 제한

001~005 이후 `20260914000600_hr_module_settings.sql` 마이그레이션을 적용하고 새 앱을 배포한다. 이번 작업에서는 운영 DB 적용·배포를 수행하지 않았다. 신규 RPC가 없는 환경에서 설정 화면은 오류를 표시하며 데모 설정으로 대체하지 않는다.

현재 구현된 인사 기본 모듈에 실제 제어가 적용된다. 향후 근태·휴가·급여 등을 구현할 때 각 모듈의 결재 대기·미마감·외부 전송과 종속 기능 검사를 추가해야 하며, 모듈 목록에 표시된다고 해당 기능이 개발된 것은 아니다.

## 검증

전체 Vitest 65개 파일·771개 테스트, ESLint, 프로덕션/PWA 빌드를 통과했다. 새 PostgreSQL 검증 61개는 실제 선행 마이그레이션과 기존 직원·예약 발령 데이터를 포함한다. PGlite는 단일 백엔드이므로 실제 두 세션 동시 잠금 경합은 검증하지 못했다.

실제 Vue 컴포넌트를 모의 데이터로 렌더링해 1440px·375px 화면과 변경 검토를 확인했다. 가로 넘침과 브라우저 실행 오류는 없었다. 운영 서버 연동 검증은 배포 후 별도로 필요하다.
