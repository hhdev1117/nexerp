# 직원 명부·인사발령 운영 안내

## 현재 구현

`인사관리 > 직원 · 인사발령`(`/hr/employees`)에서 현재 회사 직원 명부를 검색·페이지 조회하고 직원을 등록한다. 사번, 이름, 입사일, 주 사업장, 부서·직급·직책 코드, 선택적 로그인 계정 연결을 저장한다. 민감 개인정보·급여정보는 수집하지 않는다.

직원별 주 소속 변경·퇴사 발령을 날짜와 사유로 기록하고 이력을 조회한다. 예약 발령은 별도 스케줄러 없이 서버 요청 시 서울 기준 날짜로 판정한다. 퇴사 발효일은 첫 비재직일이다. 퇴사 후에도 마지막 소속과 발령 이력을 보존하며 전사 권한 정책을 이전 버전으로 복원해도 퇴사자의 접근은 복원되지 않는다.

현재 발령은 인사담당자가 직접 기록하는 방식이다. 별도 승인·결재 흐름은 아직 연결하지 않았다. 미래의 마지막 미취소 발령만 취소할 수 있으며 취소 사유·작업자를 보존한다. 오늘 또는 과거에 적용된 발령은 취소할 수 없다. 같은 직원의 같은 발효일은 취소 이후에도 재사용하지 않으며, 기존 미취소 발령보다 뒤 날짜로 기록한다.

## 권한 설정 순서

1. 마이그레이션 001~004를 순서대로 적용한다. 기존 001~003이 적용된 환경에는 `20260914000400_hr_employee_ledger.sql`을 추가한다.
2. 기술 관리자가 `전사 권한관리`에서 회사와 인사담당 계정을 연결한다.
3. 해당 계정의 등급·역할에 `직원 · 인사발령`의 `메뉴`, `조회`를 **회사 전체** 범위로 부여한다. 등록 담당자는 `생성`, 발령 담당자는 `수정`도 부여한다. 정책을 저장하고 발행한다.
4. 담당자가 해당 회사를 선택해 직원 명부를 연다. 로그인 계정은 발행된 회사 정책의 연결 가능한 계정 중 선택한다. 계정 없이 직원을 등록하는 것도 가능하다.
5. 직원의 직급·직책 코드를 정책의 매핑 코드와 동일하게 입력한다. 예: 직급 `STAFF`→레벨1, 직책 `TEAM_LEAD`→레벨4. 계정에 직접 등급을 지정했다면 해당 등급이 우선한다.

최초 정책 발행의 전사 전환 조건은 [전사 권한 안내](enterprise-access.md)를 먼저 확인한다. 기술 관리자라는 이유만으로 직원 데이터를 조회할 수는 없다. 인사 원장의 생성·수정은 계정 연결과 직급·직책 변경을 통해 업무 권한에 영향을 주므로 신뢰하는 담당자에게만 부여한다.

이번 단계는 회사 전체 범위만 지원한다. 본인·부서·사업장 범위를 자동으로 확대하지 않는다. 인사 리소스에 유효한 개별 거부가 있으면 해당 행동을 보수적으로 차단하며, 좁은 범위의 거부도 회사 전체 허용으로 우회하지 않는다.

## 데이터와 보호

`hr_employees`는 직원 등록 원장, `hr_personnel_actions`는 발령·취소 감사 이력이다. 테이블 직접 접근은 차단하고 RLS를 활성화했다. 조회·변경은 서버에서 현재 사용자와 회사별 발행 정책을 검증하는 RPC만 사용한다. 직원·사업장 참조는 회사 복합 외래키로 제한한다. 동일 회사의 사번과 계정 연결은 중복되지 않는다. 발령·취소는 직원 행 잠금과 예상 버전 검사로 동시 변경 충돌을 차단한다.

직원 등록은 회사 소속 권한을 새로 만들지 않는다. 기존 발행 멤버십이 유효한 계정에 대해서만 현재 직원의 입사·퇴사 상태와 주 소속 정보를 반영한다. 연결되지 않은 기존 정책 계정은 기존 정책 값으로 동작한다. 회사 전환과 로그아웃 시 화면 데이터·편집창을 비우며 늦게 도착한 응답을 폐기한다.

## 남은 범위

이름 등 기본정보 정정, 등록 후 계정 연결 변경, 재입사 고용 회차, 조직·직급·직책 마스터, 겸직, 과거 이관·소급 정정, 발령 결재, 모듈 사용 설정은 후속 단계다. 현재 등록 사번·기본정보·계정 연결은 변경하지 않는 방식이므로 운영 입력 전 확인이 필요하다. 전체 인사관리 기능이 완료된 상태는 아니다.

운영 DB 적용·배포는 이번 작업에서 수행하지 않았다. 로컬 SQL 검증은 Auth 헬퍼를 대체한 PGlite 환경이며 전체 Supabase Auth/pgTAP 통합 검증을 대신하지 않는다.

## 검증 기록

2026-09-14 전체 Vitest 61개 파일·726개 테스트, ESLint, production build 통과. 1440px/375px에서 실제 Vue 컴포넌트를 예시 데이터로 렌더링하여 직원 목록과 퇴직 확인창의 가로 넘침·페이지 오류가 없음을 확인했다. SQL 실행 검증은 PGlite에서 43개 단언을 통과했다. 예약 전후의 실제 메뉴 변화와 직접 등급 우선순위도 검증했다.
