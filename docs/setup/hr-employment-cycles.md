# 고용 회차·재입사 운영 안내

## 현재 구현

직원 상세의 **고용 이력**은 최초 입사와 각 재입사를 별도 회차로 보존한다. 사번과 직원 식별자는 유지하며, 회차마다 입사일·퇴사일·사업장·부서·직급·직책과 발령 이력을 기록한다. 기존 직원과 발령은 마이그레이션 때 1회차로 이관된다.

퇴사한 직원은 이전 퇴사일 다음 날 이후의 미래 날짜로 재입사를 예약할 수 있다. 같은 날 재입사, 회차 기간 중복, 재직 중이거나 이미 재입사 예정인 직원의 추가 회차는 서버가 차단한다. 서울 날짜 기준으로 입사일 전에는 예정 상태이고 로그인 권한도 생기지 않으며, 입사일부터 해당 회차의 직급·직책·소속이 권한 계산에 반영된다.

## 계정과 취소

재입사 등록 시 로그인 계정을 유지하거나, 연결 해제하거나, 다른 회사 정책 계정으로 바꿀 수 있다. 화면에서 저장 전 사업장·소속·계정과 예상 권한 레벨을 함께 검토한다. 직접 지정 레벨, 직책 매핑, 직급 매핑 순서로 적용되는 기존 정책은 그대로 유지한다.

아직 시작하지 않은 재입사 회차는 취소 사유와 영향 확인을 거쳐 취소할 수 있다. 예약 등록 때 계정을 변경했고 이후 별도 계정 변경이 없었다면 취소 시 이전 계정으로 복원한다. 이후 담당자가 계정을 다시 변경했다면 그 최신 변경을 유지한다. 회차와 계정 변경·복원은 모두 감사 이력에 남는다.

## 권한과 모듈 상태

이력 조회에는 `hr.core/read/company`, 재입사 등록과 예정 회차 취소에는 `hr.core/update/company`가 필요하다. 등록은 인사 기본 모듈이 **사용** 상태일 때만 가능하다. 예정 회차 취소는 **사용** 또는 **진행 건 정리** 상태에서 가능하고, 읽기 전용·사용 중지 상태에서는 차단된다. 기술 관리자도 발행된 업무 권한 없이 직원 이력을 조회하거나 변경할 수 없다.

미래 발령과 미래 고용 회차가 있으면 모듈의 예약 건수에 함께 포함된다. 읽기 전용이나 사용 중지로 바꾸기 전에 진행 건 정리 상태에서 해당 회차가 시작되기를 기다리거나 취소해야 한다.

## 데이터와 적용

`hr_employment_cycles`가 고용 회차를 저장하고 `hr_personnel_actions.employment_id`가 발령을 정확한 회차에 연결한다. 활성 회차는 `hire_date <= 서울 기준일`이고 `end_date`가 없거나 기준일보다 뒤인 미취소 회차다. 테이블 직접 접근은 허용하지 않으며 RLS와 보안 RPC가 회사·권한·모듈 상태·직원 버전을 검증한다.

001~007 이후 `20260915000800_hr_employment_cycles.sql`을 적용하고 앱을 배포한다. 이번 작업에서는 운영 DB 적용과 배포를 수행하지 않았다. 적용 전 백업과 스테이징 검증을 거치고, 앱보다 마이그레이션을 먼저 적용해야 한다.
